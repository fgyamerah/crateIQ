[2026-08-06] — Waveform W6 lifecycle, cleanup, and resource controls

- Added `backend/app/services/waveform_cache_service.py`: bounded cache
  accounting, tiered cleanup, LRU eviction, startup reconciliation, and the
  manual preview/clear action. Every deletion is structurally contained —
  candidates are derived internally from the validated cache root and
  CrateIQ's own artifact/temp naming, the walk never follows symlinks, and
  each candidate must still pass W1's containment assertion.
- Cleanup runs in ascending order of regret: abandoned temp files (>24h),
  then aged-out superseded schema/algorithm layouts (>7d), then orphan
  artifacts nothing references, then artifacts whose track is no longer
  `ready`, and only then least-recently-used ready artifacts. The first two
  tiers run unconditionally because neither can ever be served; the rest run
  only above the 2 GiB limit and prune to 80% of it. A just-published
  artifact is protected so a publication cannot immediately evict itself.
- LRU ordering uses a new application-owned `waveform_track_state
  .last_accessed_at` column rather than filesystem `atime`, which
  `relatime`/`noatime` mounts defer or disable. The waveform GET records
  access at most once per track per hour, so polling from several tabs cannot
  amplify into a write per request.
- Scheduler shutdown is now ordered and idempotent: stop accepting work,
  cancel every in-flight cancellation token so W2's supervisor can TERM/KILL
  and reap the child process group, wait a bounded grace period, then cancel
  the worker tasks. Jobs still active are recorded as `BACKEND_SHUTDOWN`,
  distinct from a user cancellation, and are never resumed.
- An unexpected runner exception now marks the job `failed` with
  `WAVEFORM_WORKER_FAILED` instead of stranding it in `processing`, which
  would have permanently occupied that track's active-job index and blocked
  every future request for it.
- Added operational-row retention: failed/cancelled job rows and quiet,
  artifact-less track states expire after 30 days. Rows only — no artifact,
  source, or trusted pipeline row is touched. Succeeded job rows are kept.
- Completed W3's deferred `detected` -> `ready` readiness transition without
  breaking the no-subprocess guarantee on `GET /api/runtime/readiness`. A
  bounded `ffmpeg -version` / `ffprobe -version` check runs once at startup
  and caches its result; the readiness report only reads that cache. No media
  path is passed to either binary.
- Added `GET /api/waveform-cache` (read-only footprint plus clear preview)
  and `POST /api/waveform-cache/clear`, which requires `{"confirm": true}`
  and returns `400 WAVEFORM_CACHE_CLEAR_NOT_CONFIRMED` otherwise. A confirmed
  clear removes only CrateIQ-owned cache files, resets affected tracks to
  `stale`, and queues no replacement work.
- Fixed a latent hazard in the shared maintenance lock: an `asyncio.Lock`
  created at import binds to the first loop that awaits it and refuses any
  other. The lock is now created per running loop, matching the scheduler's
  existing tolerance for being restarted under a new loop.
- Verified: 1327 tests pass, twice, against the 1191-test W3 baseline
  (W4/W5 were frontend-only). `npm --prefix frontend run typecheck` passes
  unchanged. Containment is proven against a source file, the cache root, the
  library root, traversal paths, a symlinked file, a symlinked directory, an
  unknown filename, a directory holding a foreign file, and a cache root
  overlapping the library.
- Files affected: `backend/app/services/waveform_cache_service.py` (new),
  `waveform_job_service.py`, `waveform_scheduler.py`,
  `waveform_readiness_service.py`, `backend/app/api/routes/waveforms.py`,
  `backend/app/schemas/waveform.py`, `backend/app/core/db.py`,
  `backend/app/main.py`, `tests/test_waveform_cache_cleanup.py` (new),

[2026-08-06] — Waveform W3 generation lifecycle, cache, and API

- Connected W1's state foundation to W2's extractor with an explicit,
  demand-driven generation workflow. New endpoints:
  `GET /api/tracks/{id}/waveform` (read-only state/peaks, ETag + 304),
  `POST /api/tracks/{id}/waveform/generate` (the only way to create work),
  `GET /api/waveform-jobs/{id}` and `DELETE /api/waveform-jobs/{id}`.

[2026-04-12] v1.7.0 — Artist merge: three-category classification, normalization fix, tests
----------------------------------------------------------------------

TYPE: feature / bug fix

SUMMARY:
Refactored artist-merge classification so that punctuation/casing/hyphen variants
(e.g. "Heavy-K" / "Heavy K", "H.O.S.H" / "HOSH") are correctly recognised as
safe aliases instead of being marked ambiguous. Introduced three explicit merge
categories and 77 new tests.

DETAILS:
Root cause of the bug:
  The old _classify_merge() compared fi.primary_artist.lower() directly.
  "Heavy-K".lower() = "heavy-k" ≠ "heavy k" = "Heavy K".lower(), so despite
  being grouped correctly, the comparison flagged them as different primaries.

Fix:
  New _normalize_primary_for_compare() applies the same transforms used by
  normalize_artist_key() (period strip, hyphen→space, etc.) before comparison.
  Now "Heavy-K" and "Heavy K" both normalize to "heavy k" → SAFE_ALIAS.

Three merge categories (replacing the old binary safe/unsafe):
  SAFE_ALIAS          — formatting/punctuation/casing differences only; no collab.
                        Examples: "Heavy-K" / "Heavy K", "H.O.S.H" / "HOSH",
                        "Rosalie" / "Rosalie.", "culoe de song" / "Culoe De Song"
  SAME_PRIMARY_COLLAB — same primary after normalization; ≥1 folder has feat/comma.
                        Examples: "Heavy-K" / "Heavy-K feat. Davido"
  AMBIGUOUS           — primary artists differ after normalization; never auto-merged.

Other improvements:
  - _describe_alias_differences() generates human-readable reason strings:
      "capitalization variant", "dotted-initials variant", "hyphen/space variant",
      "trailing period variant", "period variant", "underscore/space variant",
      "quotation style variant"
  - _pick_canonical() penalises all-uppercase names (e.g. HOSH loses to H.O.S.H)
    and all-lowercase names; mixed-case preferred.
  - FolderInfo.has_collab_suffix field added (populated at scan time).
  - MergeGroup.merge_category field added.
  - build_merge_groups() returns (safe, ambiguous) where safe = SAFE_ALIAS +
    SAME_PRIMARY_COLLAB groups; ambiguous = AMBIGUOUS only.
  - JSON report restructured with safe_alias_merges, same_primary_collab_merges,
    ambiguous_merges sections.
  - Console output shows all three categories with clear labels.
  - New constants: MERGE_CATEGORY_SAFE_ALIAS, MERGE_CATEGORY_SAME_PRIMARY_COLLAB,
    MERGE_CATEGORY_AMBIGUOUS.

FILES:
  modules/artist_merge.py     — full refactor (normalization fix, new functions,
                                 updated dataclasses, report structure)
  tests/test_artist_merge.py  — new: 77 tests across 7 test classes

IMPACT:
  - Behaviour change: groups that were previously marked AMBIGUOUS (and skipped)
    because of hyphen/period/case differences are now correctly classified as
    SAFE_ALIAS and auto-applied in --apply mode.
  - No change to file-move logic, DB updates, or other pipeline steps.

[2026-04-11] v1.3.0 — Sanitizer: strip leading track-index junk before pipe
----------------------------------------------------------------------

TYPE: feature / patch

SUMMARY:
- New regex rule in sanitize_text() removes junk prefixes (digit, single letter,
  or symbol+digit/letter) that appear at the very start of a title before a `|`
  character and a space.  Handles DJ-pool numbering like "2 | Heartbreaker" or
  "***3 | Track (Remix)" and single-letter prefixes like "A | Charlotte".

DETAILS:
- Pattern: `^[^\w\s]*(?:\d+|[A-Za-z])\s*\|\s*`
  - `^`         — anchored to start; mid-string pipes are NEVER touched
  - `[^\w\s]*`  — zero or more leading symbol chars (e.g. `***`)
  - `(?:\d+|[A-Za-z])` — one or more digits OR exactly one letter (single-char only)
  - `\s*\|\s*`  — optional spaces around the pipe (all consumed)
- Multi-letter words before a pipe (e.g. "Rock | Roll", "Day | Night") are
  preserved because the single `[A-Za-z]` token requires the next char to be
  the pipe, not another word character.
- Runs as Step 0 in sanitize_text(), before URL and promo-phrase passes.
- 8 new test cases added to TestSanitizeText.

FILES:
- modules/sanitizer.py     — added _RE_PIPE_JUNK_PREFIX regex + Step 0 in sanitize_text()
- tests/test_sanitizer.py  — 8 new tests for the pipe-prefix rule

IMPACT:
- Any title/field string starting with a short numeric or single-letter index
  before a `|` will now be cleaned automatically in the sanitize pass.
- No impact on MIK BPM/key/cue data (sanitizer never touches those fields).
